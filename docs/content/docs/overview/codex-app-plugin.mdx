# Codex App Plugin

The plugin lets Codex open Infinite Canvas, inspect nodes, create content, connect generation flows, and start generation directly from a conversation. Its source is in `plugins/infinite-canvas/`.

## First-time setup

### 1. Install the plugin

The easiest option is to send this request to Codex:

```text
Install the Infinite Canvas Codex plugin from https://github.com/basketikun/infinite-canvas.git.
Clone it to ~/plugins/infinite-canvas, add that repository to Codex marketplace,
then install infinite-canvas@infinite-canvas-local.
When finished, check the plugin and MCP status and tell me to start a new conversation.
```

Or run the commands yourself:

```bash
git clone https://github.com/basketikun/infinite-canvas.git ~/plugins/infinite-canvas
codex plugin marketplace add ~/plugins/infinite-canvas
codex plugin add infinite-canvas@infinite-canvas-local
```

Start a new Codex conversation after installation. Existing conversations do not reload newly installed Skills or MCP tools.

### 2. Open and connect the canvas

Send this in the new conversation:

```text
Open a new Infinite Canvas board and connect it to Codex
```

Codex normally:

1. Starts the local Canvas Agent.
2. Opens `https://canvas.best/` and creates a canvas.
3. Passes the local Agent connection details to the page.
4. Opens the Infinite Canvas Agent panel on the right.

Codex starts a local frontend instead of the hosted site only when you explicitly ask for it.

### 3. Confirm the connection

The setup is ready when the Agent panel says Connected. You normally do not need to enter the Local URL or Connect token manually.

Verify the tool connection with a read-only request:

```text
Read the current canvas and summarize its node structure
```

If the canvas is empty, a node count of 0 is the expected result. Create a few nodes and try again.

## Common requests

| Goal | Request |
| --- | --- |
| Inspect the canvas | `Read the current canvas and summarize its node structure` |
| Inspect the selection | `Read the selected nodes and explain how they relate` |
| Create content | `Create three text nodes in empty viewport space with three coffee poster directions` |
| Organize content | `Group the selected nodes by image, prompt, and configuration, then move them into three vertical areas` |
| Build a flow | `Build an image generation flow from the selected prompt and image, but do not start generation` |
| Edit nodes | `Change the selected text node title to "Product highlights" and keep the body unchanged` |
| Connect nodes | `Connect the selected text node to the image configuration node on the right` |

For actions that may cost money, ask Codex to create the flow without generating first. Review the nodes and settings, then request generation separately.

## Using the connection panel

Click the connection status at the top of the Agent panel to open connection settings.

### Automatic status

The panel distinguishes not detected, installed, connecting, MCP starting, connected, and failed states, then shows only the action needed:

- Not detected: show the installation request.
- Installed but disconnected: show the request that reopens the canvas.
- MCP starting: wait for tools to initialize.
- Connected: go straight to chat.
- Failed: show checks for the plugin, local Agent, MCP, and token.

Suggested tasks follow the current canvas state: empty, populated, connected, or selected. Clicking fills the input only; it does not send a request or start a paid generation.

### Connection details

No changes are needed when the plugin connects successfully. Check these fields only when discovery fails:

- `Local URL`: local Agent address, usually `http://127.0.0.1:17371`.
- `Connect token`: token generated by the local Agent.
- Connect button: reconnect or disconnect the current Agent.

### Advanced settings

Expand Advanced settings to start the Agent manually or remove the plugin and MCP. To troubleshoot the web connection, run:

```bash
npx -y @smithhsiiiii/canvas-agent@latest
```

Keep the terminal open and reconnect from Connection details. This command provides the web connection service but does not install the Codex MCP.

### Plugin and MCP management

Use these commands only when uninstalling or checking leftover configuration:

```bash
codex plugin remove infinite-canvas
codex mcp remove infinite-canvas
```

## Troubleshooting

| Symptom | Cause and action |
| --- | --- |
| Codex cannot see the plugin tools after installation | Start a new Codex conversation so Skills and MCP tools reload |
| The page says disconnected | Confirm the local Canvas Agent is running, then reconnect from Connection details |
| MCP is ready but the page is still disconnected | MCP tools and the web connection service are separate processes; ask Codex to reopen and reconnect the canvas |
| Reading the canvas returns 0 nodes | The canvas is empty; this is not a connection failure |
| The `npx` command fails | Confirm Node.js is available and read the terminal error |
| Skill changes do not appear | Refresh or reinstall the plugin, then start a new conversation |

## Update the plugin

Normal web changes do not require reinstalling the plugin. Refresh the plugin and start a new conversation only after changing:

- `plugins/infinite-canvas/.codex-plugin/plugin.json`
- `plugins/infinite-canvas/.mcp.json`
- `plugins/infinite-canvas/skills/`
- MCP tools or plugin entry scripts

## Development from this repository

From the repository root:

```bash
codex plugin marketplace add "$(pwd)"
codex plugin add infinite-canvas@infinite-canvas-local
```

The repository's `.agents/plugins/marketplace.json` already points to `./plugins/infinite-canvas`.

## How the connection works

There are two processes when troubleshooting:

| Process | Start command | Purpose |
| --- | --- | --- |
| Plugin MCP | `npx -y @smithhsiiiii/canvas-agent@latest mcp` | Exposes canvas tools to Codex |
| Web connection service | `npx -y @smithhsiiiii/canvas-agent@latest` | Receives canvas state and provides the Local URL / Connect token |

The plugin Skill handles both during normal use. Check the web connection service only when MCP is ready but the page remains disconnected.
