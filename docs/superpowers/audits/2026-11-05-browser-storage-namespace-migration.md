# 浏览器存储命名空间正式迁移验收

## 结论

浏览器持久化已从旧命名空间切换到版本化命名空间，并完成隔离 Chromium 环境验收。首次启动会复制旧数据、逐仓校验、保存本地偏好备份，全部通过后才写入迁移标记并启用新库；任一失败都会继续使用旧库。旧数据库、旧插件库和旧偏好键没有删除或改名。

本轮未发布 npm、未构建或部署生产镜像、未修改生产环境，也没有清理真实用户的旧库。

## 命名空间

| 项目 | 旧命名空间 | 新命名空间 |
| --- | --- | --- |
| 主数据库 | `infinite-canvas` | `infinite-canvas-v1` |
| 插件数据库 | `infinite-canvas-plugins` | `infinite-canvas-plugins-v1` |
| 本地偏好 | 原始 key / `infinite-canvas:*` | `infinite-canvas:v1:*` |
| 手动旧库回退 | 无 | `infinite-canvas:v1:storage-namespace-override=legacy` |

`app_state` 中的旧 key 在复制时去掉 `infinite-canvas:` 前缀；其他对象仓库的主键保持不变。`migration_meta` 保存迁移 owner、迁移标记和 localStorage 值备份。

## 迁移顺序

1. 检查新迁移标记和旧库；未知标记版本直接失败关闭。
2. 在 Web Lock 内只读扫描旧主库、旧插件库和受管本地偏好。
3. 检查浏览器配额是否足够容纳新增副本。
4. 在目标库写入 owner，再逐仓复制记录。
5. 校验对象仓库 schema、主键集合、记录数、Blob/ArrayBuffer 大小、关键项目/节点/连线/资产 ID。
6. 校验 localStorage 新旧值一致并备份原始键值。
7. 写入迁移标记，页面渲染和 store hydration 完成后才切换到新库。

## 浏览器证据

- 隔离源使用 8 个主库对象仓库、画布、资产、工作流、图片预览、媒体、生图和视频记录、提示词缓存、插件库以及 9 个本地偏好键。
- 迁移后同时存在旧主库、新主库、旧插件库和新插件库；新主库包含 `owner`、`local-preferences-backup` 和 `migration` 三条迁移元数据。
- 新库中 `app_state` 使用 `canvas_store`、`asset_store`、`workflow_store`；画布项目、节点、连线、图片预览、媒体、日志、提示词缓存和插件设置均可读取。
- 页面恢复英文、浅色主题、故事板偏好和已有画布；画布列表显示 2 个节点和 1 条连线。
- 再次刷新后迁移标记时间、记录数和对象仓库计数不变，旧库仍存在。
- 设置手动覆盖为 `legacy` 后，配置页显示旧命名空间和警告；移除覆盖后恢复新命名空间。
- 把迁移标记版本改成未知值后，页面继续使用旧库并显示对应失败原因；恢复正常标记后重新进入新库。
- 将画布持久化 JSON 改成损坏内容后，迁移在创建新库前失败，旧库保留，配置页显示 `storage-json-record-damaged`。
- 本地偏好、插件库和旧主库的原始值在成功迁移后均保持不变。
- 清空隔离测试 origin 后重新加载，只创建 `infinite-canvas-v1`，其中包含 10 个应用对象仓和 `migration_meta`；迁移标记的 `sourceDatabase` 为空，旧主库没有创建，二次刷新不重写标记时间。

## 边界

- 旧库清理没有实现；至少保留一个版本的恢复入口。
- 隔离验收使用合成数据，真实用户的大图片、长日志和浏览器配额仍需在正式发布前确认。
- 当前迁移按对象仓库读取记录并在内存中校验；大体积媒体库需要继续观察峰值内存和迁移耗时。
- 迁移成功后如果用户主动删除某项设置，应用会同时删除新旧 key，避免以后切换旧库时复活已删除配置。
