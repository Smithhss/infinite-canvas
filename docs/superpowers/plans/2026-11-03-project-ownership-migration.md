# Infinite Canvas 项目自有化迁移

**状态：** 阶段 A 已在本地完成，尚未提交、推送或发布。

**目标：** 在保留 MIT 原始版权和必要兼容边界的前提下，让用户入口、发布链路、扩展生态、视觉语言和文档逐步归属当前项目，不再依赖上游品牌与公共发布地址。

## 原则

1. 先完成可验证兼容，再替换名称；不因品牌迁移破坏已有安装、插件更新或用户数据。
2. 不复制 LibTV 或其他产品的源码、字体、图标、图片和受版权保护的素材，只借鉴信息层级、密度和交互原则。
3. 所有迁移按阶段验收，每个阶段都能单独回滚。
4. 浏览器本地数据迁移必须先备份、版本化、校验和原子写入；未知版本或损坏数据拒绝覆盖。
5. 未经明确授权，不提交、不推送、不发布镜像、不上架 npm 包、不部署生产。

## 阶段 A：入口和构建归属

**状态：** 本地完成。

- README、文档首页、侧栏、插件元数据、版本检查和页内文档入口指向当前仓库。
- 删除上游赞助、QQ、社区、Star History、远程宣传图和在线体验入口。
- Docker Compose 默认从当前源码构建。
- GitHub Actions 使用显式小写 GHCR 镜像名。
- 保留 MIT 原始版权声明。
- 清理确认无引用的组件、死导出和旧本地部署文件。

**验收：**

- 页面和文档不再主动跳转到上游宣传、社区或体验站。
- `docker compose config` 可解析源码构建配置。
- `git diff --check`、Web 测试、类型检查和构建通过。

## 阶段 B：插件与 npm 发布链

**状态：** 待开始。

### B1 自有插件 registry

**状态：** 已完成远端发布和线上验证。

- 清单已升级到 `schemaVersion: 1`，包含 SHA-256、大小、最低应用版本和平台。
- 构建后、CI 发布前和前端安装前分别执行制品校验；任一条目非法时整份清单失败关闭。
- 官方默认地址已切到当前仓库，浏览器已验证加载、安装、更新、禁用、启用、卸载和刷新持久化。
- 验收记录见 `docs/superpowers/audits/2026-11-03-plugin-registry-acceptance.md`。
- 已随 `v0.24.0` 发布到 `plugins-dist`，GitHub Actions 和 jsDelivr 在线制品均通过验收。

1. 固定插件清单格式、版本字段、下载地址和校验方式。
2. 在仓库内建立可发布的 `plugins-dist` 制品流程。
3. 为版本、最低应用版本、架构兼容和签名/校验增加失败关闭策略。
4. 将应用默认 registry 从上游切换到自有地址，但保留一次性兼容回退。
5. 验证安装、更新、回滚、离线失败和未知插件。

**停止线：** 自有 registry 没有稳定制品或校验机制时，不切换默认地址。

### B2 自有 npm 包

**状态：** 已完成新包发布与在线验收，旧包继续保留兼容窗口。

1. `@smithhsiiiii/canvas-agent@0.7.0` 和 `@smithhsiiiii/canvas-proxy@0.2.0` 已公开发布。
2. 网页连接面板、本地代理页签和 Codex 插件入口已切换到新包。
3. 旧 `@basketikun/*` 包在兼容窗口内继续可用。
4. 后续再确定旧包弃用时间、迁移截止和回滚窗口。

**停止线：** 新包没有通过干净环境安装、启动、Agent 连接和代理透传测试前，不删除旧包提示。

## 阶段 C：浏览器存储命名空间

**状态：** 高风险，暂缓。

当前使用 `infinite-canvas` IndexedDB、`infinite-canvas:*` localForage key 和故事板折叠偏好。直接改名会丢失画布、资产、生成历史或设置。

迁移顺序：

1. 只读扫描旧库，生成项目数、节点数、连接数、资产数、生成记录数和占用体积摘要。
2. 在临时新库写入完整副本，不删除旧库。
3. 逐项校验 schema、版本、关键 ID、二进制大小和可读取性。
4. 写入迁移标记；应用首次启动时优先读取新库。
5. 至少保留一个版本的双读或恢复入口。
6. 用户确认后才提供清理旧库操作。

**停止线：** 任一未知版本、损坏记录、空间不足或校验失败都必须停止迁移并保留旧库。

## 阶段 D：自有视觉和产品语言

**状态：** 持续进行。

- 将画布、故事板、素材库、工作台和文档统一到自有 token 和组件语言。
- 继续降低工具 chrome，提高媒体内容密度，但保留清晰状态和可访问性。
- 为故事板补充更大规模性能数据，只在有明确卡顿证据时采用虚拟列表。
- 建立固定截图基线：1440×900、390×844、深色、浅色和代表性 52/100+ 素材项目。
- 所有视觉借鉴都必须记录为“原则复现”，不复制源站资源或代码。

## 完成定义

- 用户可见入口不再依赖上游品牌、宣传页或公共镜像。
- 自有 Agent、代理和插件具备独立发布、升级、回滚能力。
- 存储迁移经过版本化校验且不会覆盖未知或损坏数据。
- 自有视觉 token、故事板与工作流交互形成稳定基线。
- 所有阶段均有自动化结果、浏览器证据、剩余风险和回滚说明。
